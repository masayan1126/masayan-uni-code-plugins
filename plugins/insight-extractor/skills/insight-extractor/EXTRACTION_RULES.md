# 抽出ルール

## 入力形式

以下のいずれかを受け付ける：
- URL（Webページ）
- テキスト（文章・長文）

## 抽出対象（好ましい内容）

### 1. 体験・経験ベースの内容
- 筆者の実際の体験に基づくユースケース
- 具体的な活用事例（数値・結果を含むもの）
- 失敗談や学びを伴うエピソード
- 「〜してみた」「〜を試した結果」などの実践報告

### 2. 専門知識・独自の視点
- 筆者の専門性に基づく洞察
- 独自の考え方やフレームワーク
- 他では見られない切り口での分析
- 深い理解に基づく解説

### 3. ベストプラクティス・アンチパターン
- 推奨される手法や設計パターン
- 避けるべきアンチパターン
- 具体的なコード例やコマンド例を伴う実践的なガイド
- 「〜すべき」「〜は避けるべき」の根拠が明確なもの

## 除外対象（好ましくない内容）

- 一般的すぎる説明（「〜とは」のような定義のみ）
- 抽象的で具体性に欠ける内容
- 根拠や出典が不明確な主張
- 公式ドキュメントの丸写し・要約のみ
- 他サイトからの引用のみで構成された内容
- 実体験を伴わない机上の理論

## 出力形式

```markdown
## インサイトまとめ

### 1. [インサイトのタイトル]
📍 **位置**: [ページ内の位置（例: 冒頭、中盤、後半、「見出し名」セクション付近）]

> 抜粋テキスト（原文から簡潔に引用）

💡 **ポイント**: [なぜこれが価値あるか1-2文で説明]

---

### 2. [インサイトのタイトル]
...
```

## 位置情報の記載ルール

抜粋がページのどこにあるか特定できるよう、以下のいずれかを記載：

1. **見出し名**: 「## 〇〇」セクション内、「### △△」の下
2. **相対位置**: 冒頭 / 序盤 / 中盤 / 後半 / 末尾
3. **目印となる要素**: 「〇〇の図の後」「コードブロックの前」など

## 処理手順

1. URLの場合：WebFetchでコンテンツを取得
2. テキストの場合：そのまま分析開始
3. 抽出対象の条件に合致する箇所を特定
4. 各インサイトの位置情報を記録
5. 出力形式に従ってまとめを作成
6. 抽出したインサイトがゼロの場合、その旨を報告

## 注意事項

- 著作権に配慮し、抜粋は最小限にとどめる
- 抜粋は15語以内を目安とし、要点を伝える
- 価値の低い内容を無理に抽出しない
- 該当するインサイトがない場合は正直に報告する
