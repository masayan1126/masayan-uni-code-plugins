# 実行ワークフロー

このドキュメントでは、Chrome拡張機能企画スキルの詳細な実行手順を説明します。

## 実行手順

### 1. 初期ヒアリング

ユーザーから以下の情報を収集（提供されていない場合は質問）：

#### 必須項目

- **拡張機能のテーマ・分野**: どのような領域か（生産性向上、SNS、開発者向け、コンテンツ、セキュリティなど）
- **解決したい課題**: ユーザーのどんな問題を解決するか
- **ターゲットブラウザ**: Chrome専用か、他ブラウザ対応も検討するか
- **公開方法**: Chrome Web Store / 社内配布 / 個人利用のみ

#### オプション項目

- **ターゲットユーザー**: 想定している利用者層
- **収益モデル**: 無料 / 有料 / フリーミアム / 広告
- **参考拡張機能**: 参考にしているか類似の拡張機能
- **外部API連携**: 使用したいWeb APIやサービス

### 2. アイデアブレインストーミング

ユーザーの入力を基に、複数の拡張機能アイデアを生成：

#### 2-1. 利用シーンの深掘り

- ペルソナ設定（具体的なユーザー像）
- ブラウザ利用シナリオ
- 既存の解決方法とその不満点

#### 2-2. アイデアの発散

- 3〜5パターンの拡張機能コンセプトを提案
- 各アイデアの独自性と差別化ポイント
- 類似拡張機能との比較

### 3. 市場・競合分析

選定したアイデアに対して市場調査を実施：

#### 3-1. 競合拡張機能の調査

- WebSearchツールでChrome Web Storeの類似拡張を調査
- 競合のレビュー・評価を分析
- 機能比較と差別化ポイントの特定

#### 3-2. 市場ニーズの把握

- ターゲットユーザーの規模推定
- 類似拡張のダウンロード数・評価数を参考
- 需要のトレンド分析

### 4. MVP機能設計

最小限の機能で拡張機能を立ち上げるための設計：

#### 4-1. コア機能の定義

- 必須機能（Must Have）: 3〜5個に絞る
- 重要機能（Should Have）
- あったらいい機能（Nice to Have）

#### 4-2. UI/UX設計

- Popup UI設計
- Options ページ設計
- Content Script の注入範囲
- コンテキストメニュー設計（右クリックメニュー）

#### 4-3. データ設計

- chrome.storage の利用計画
- 同期データ vs ローカルデータ
- データ容量の見積もり

### 5. Chrome API・権限設計

#### 5-1. 使用するChrome API

| API名 | 用途 | 権限 |
|------|------|------|
| tabs | タブ操作 | tabs |
| storage | データ保存 | storage |
| contextMenus | 右クリックメニュー | contextMenus |
| notifications | 通知表示 | notifications |
| ... | ... | ... |

#### 5-2. 必要な権限（permissions）

- 最小権限の原則に基づき選定
- host_permissions の範囲設計
- optional_permissions の活用

#### 5-3. Manifest V3設計

- background: Service Worker設計
- content_scripts: 注入スクリプト設計
- action: ツールバーアイコン設計

### 6. 実装ロードマップ作成

段階的な開発計画を策定：

#### 6-1. Phase 1: MVP開発（2〜4週間）

- コア機能の実装
- 基本的なUI
- ローカルテスト

#### 6-2. Phase 2: 公開準備（1〜2週間）

- Chrome Web Store用アセット準備
- プライバシーポリシー作成
- ストア申請・レビュー対応

#### 6-3. Phase 3: 改善・拡張（公開後）

- ユーザーフィードバック収集
- 機能追加・バグ修正
- 多ブラウザ対応（Edge, Firefox）

### 7. 企画書の作成と保存

全ての分析・設計内容を企画書としてまとめる：

1. 適切なファイル名を生成（例: `chrome-extension-plans/tab-organizer.md`）
2. 企画書を`chrome-extension-plans/`ディレクトリに保存
3. ファイルパスをユーザーに通知

### 8. 次のステップの提案

企画完了後、以下のアクションを提案：

- **プロトタイピング**: 基本的なPopup UIの作成
- **技術検証**: 使用予定のChrome APIの動作確認
- **アイコン作成**: 拡張機能アイコンのデザイン
- **開発着手**: 実際のコーディング開始
- **ストア準備**: スクリーンショット、説明文の準備

## 実行例

### ユーザー入力例

```
タブを整理するChrome拡張機能を作りたいです。
開いているタブをグループ化して、ワンクリックで復元できるようにしたいです。
Chrome Web Storeで無料公開したいと考えています。
```

### 実行フロー

1. 初期ヒアリング（追加質問：ターゲットユーザー、グループ化の基準）
2. アイデアブレインストーミング（3パターン提案）
3. ユーザーが選択したアイデアで競合調査（WebSearch使用）
4. MVP機能設計（保存、復元、グループ名編集の3機能）
5. Chrome API設計（tabs, storage, tabGroups）
6. 開発ロードマップ作成（4週間計画）
7. 企画書を`chrome-extension-plans/tab-organizer.md`に保存
8. 次のステップを提案（Popupデザイン、APIテスト）
