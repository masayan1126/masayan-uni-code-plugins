## 5. Chrome API・権限設計

### 5-1. 使用Chrome API

| API | 用途 | 必須/任意 |
|-----|------|----------|
| chrome.tabs | タブ情報取得・操作 | 必須 |
| chrome.storage | 設定・データ保存 | 必須 |
| chrome.contextMenus | 右クリックメニュー | 任意 |
| chrome.notifications | 通知表示 | 任意 |
| ... | ... | ... |

### 5-2. permissions

```json
{
  "permissions": [
    "storage",
    "tabs",
    "contextMenus"
  ],
  "host_permissions": [
    "https://*.example.com/*"
  ],
  "optional_permissions": [
    "notifications"
  ]
}
```

### 5-3. Manifest V3構成

```json
{
  "manifest_version": 3,
  "name": "[拡張機能名]",
  "version": "1.0.0",
  "description": "[説明]",
  "action": {
    "default_popup": "popup.html",
    "default_icon": {
      "16": "icons/icon16.png",
      "32": "icons/icon32.png",
      "48": "icons/icon48.png",
      "128": "icons/icon128.png"
    }
  },
  "background": {
    "service_worker": "background.js"
  },
  "content_scripts": [
    {
      "matches": ["https://*.example.com/*"],
      "js": ["content.js"],
      "css": ["content.css"]
    }
  ],
  "permissions": [...],
  "host_permissions": [...],
  "options_page": "options.html"
}
```

## 7. 開発ロードマップ

- ストア説明文作成
- 審査申請

**マイルストーン**: Chrome Web Store公開

### Phase 3: 改善・拡張（公開後）
- ユーザーフィードバック収集
- 機能追加・改善
- 多ブラウザ対応（Edge, Firefox）

## テンプレート使用のポイント

### 1. エグゼクティブサマリー
- 拡張機能の価値を簡潔に伝える
- 30秒で理解できる内容に

### 2. 市場・競合分析
- WebSearchで実際のChrome Web Storeを調査
- ユーザー数、評価、レビュー内容を参考に
- 最低3つの競合を分析

### 3. 機能設計
- MVPは3〜5機能に絞る
- 各機能の優先度と難易度を明記
- UI設計は具体的なサイズ・レイアウトまで

### 4. Chrome API・権限設計
- 最小権限の原則を厳守
- host_permissionsは必要なドメインのみ
- optional_permissionsを活用

### 5. 開発ロードマップ
- 現実的な期間設定（MVP: 2〜4週間）
- 各フェーズに明確なマイルストーン
- ストア審査期間も考慮（1〜3日）

### 6. 公開戦略
- 高品質なアセットを準備
- プライバシーポリシーは必須
- 多言語対応で市場拡大
