### 4-3. リソース・エンドポイント一覧

| メソッド | パス | 説明 | 認証 |
|---------|------|------|------|
| GET | /api/v1/users | ユーザー一覧取得 | 必要 |

| POST | /api/v1/users | ユーザー作成 | 必要 |
| PUT | /api/v1/users/:id | ユーザー更新 | 必要 |
| DELETE | /api/v1/users/:id | ユーザー削除 | 必要 |
| ... | ... | ... | ... |

### 4-4. スキーマ設計

#### リクエスト例（POST /api/v1/users）
```json
{
  "name": "string",
  "email": "string",
  "password": "string"
}
```

#### レスポンス例（成功）
```json
{
  "data": {
    "id": "uuid",
    "name": "string",
    "email": "string",
    "created_at": "datetime",
    "updated_at": "datetime"
  }
}
```

### 4-5. エラーレスポンス形式
```json
{
  "error": {
    "code": "ERROR_CODE",
    "message": "Human readable message",
    "details": [
      {
        "field": "email",
        "message": "Invalid email format"
      }
    ]
  }
}
```

### 4-6. HTTPステータスコード

| コード | 意味 | 使用場面 |
|-------|------|---------|
| 200 | OK | 正常取得・更新 |
| 201 | Created | リソース作成成功 |
| 204 | No Content | 削除成功 |
| 400 | Bad Request | 入力値エラー |
| 401 | Unauthorized | 認証エラー |
| 403 | Forbidden | 権限エラー |
| 404 | Not Found | リソース不存在 |
| 429 | Too Many Requests | レート制限 |
| 500 | Internal Server Error | サーバーエラー |

### 4-7. ページネーション
- **方式**: カーソルベース / オフセットベース
- **パラメータ**: `limit`, `cursor` / `offset`
- **レスポンス**: `next_cursor`, `has_more` / `total`, `offset`

```json
{
  "data": [...],
  "pagination": {
    "next_cursor": "abc123",
    "has_more": true
  }
}
```

### SLA目標
| 指標 | 目標値 |
|------|--------|
| 可用性 | 99.9% |
| レスポンスタイム（P95） | < 200ms |
| レスポンスタイム（P99） | < 500ms |
| スループット | X requests/sec |

### 監視項目
- レスポンスタイム
- エラーレート
- リクエスト数
- CPU/メモリ使用率
- データベース接続数

### アラート設定
| 条件 | 重要度 | 通知先 |
|------|--------|--------|
| エラーレート > 1% | Critical | Slack, PagerDuty |
| レスポンスタイム > 1s (P95) | Warning | Slack |
| CPU > 80% | Warning | Slack |
| 可用性 < 99.9% | Critical | Slack, PagerDuty |
