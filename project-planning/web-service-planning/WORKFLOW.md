# 実行ワークフロー

このドキュメントでは、Webサービス企画スキルの詳細な実行手順を説明します。

## 実行手順

### 1. 初期ヒアリング

ユーザーから以下の情報を収集（提供されていない場合は質問）：

#### 必須項目

- **サービスのテーマ・分野**: どのような領域のサービスか（例: SaaS, EC, コミュニティ、教育、エンタメ）
- **解決したい課題**: ユーザーのどんな問題を解決するか
- **初期予算**: 開発にかけられる予算感（個人開発、スタートアップ、企業など）
- **リリース目標時期**: いつまでにリリースしたいか

#### オプション項目

- **ターゲットユーザー**: 想定している利用者層
- **収益モデル**: どのように収益化するか（未定でもOK）
- **技術的制約**: 使いたい技術やインフラ
- **競合サービス**: 参考にしているサービス

#### PWA対応確認（必須ヒアリング）

Webサービスを企画する際は、以下のPWA対応項目を必ず確認する：

- **PWA対応の有無**: Progressive Web Appとして配布するか
- **アニメーション要件**:
  - motionライブラリでリッチなUX（ワクワクする体験）を実現するか
  - ページ遷移やインタラクションのアニメーション要件
- **ナビゲーション設計**:
  - 画面左上の戻るアイコン（ひとつ前の画面に戻る機能）
  - ブラウザバー非表示対応（display: standalone）
  - 下部ナビゲーションバーの実装
  - スマホレイアウト時はハンバーガーメニュー不要（下部固定バー表示）
  - バー表示項目のユーザー確認（表示しきれない場合は「その他」メニュー）
- **デバイス対応**:
  - iPhoneノッチ対応（セーフエリアの高さ考慮）
  - 各種スマートフォンでの表示確認
- **ホーム画面追加対応**:
  - manifest.jsonの設定
  - アプリアイコンの作成（各サイズ: 192x192, 512x512等）
  - スプラッシュスクリーン設定

### 2. アイデアブレインストーミング

ユーザーの入力を基に、複数のサービスアイデアを生成：

#### 2-1. 課題の深掘り

- ペルソナ設定（具体的なユーザー像）
- ユーザージャーニーマップ
- ペインポイントの特定

#### 2-2. アイデアの発散

- 3〜5パターンのサービスコンセプトを提案
- 各アイデアの独自性と差別化ポイント
- 類似サービスとの比較

### 3. 市場分析

選定したアイデアに対して市場調査を実施：

#### 3-1. 競合分析

- WebSearchツールを使って競合サービスを調査
- 競合の強み・弱みを分析
- 市場の隙間（ギャップ）を特定

#### 3-2. 市場規模と成長性

- ターゲット市場の規模を推定
- 成長トレンドの分析
- 参入障壁の評価

#### 3-3. 収益モデルの検討

- サブスクリプション、フリーミアム、広告、手数料など
- 競合の収益モデル分析
- 最適な価格設定の提案

### 4. MVP機能設計

最小限の機能でサービスを立ち上げるための設計：

#### 4-1. コア機能の定義

- 必須機能（Must Have）
- 重要機能（Should Have）
- あったらいい機能（Nice to Have）

#### 4-2. ユーザーフロー設計

- 主要なユーザーフロー図
- 画面遷移図
- ワイヤーフレーム（テキストベース）

#### 4-3. データモデル設計

- 主要なエンティティ
- リレーション図
- 必要なデータストア

### 5. 技術スタック選定

プロジェクトに最適な技術を提案：

#### 5-1. フロントエンド

- フレームワーク選定（React, Vue, Next.js, Nuxt.js など）
- UIライブラリ:
  - shadcn/ui（https://ui.shadcn.com/）: 推奨UIコンポーネント
  - motion（https://motion.dev/）: アニメーションライブラリ
- **ダッシュボード/管理画面系の場合**: Tremorの検討
  - Tremor（https://www.tremor.so/）: チャート・ダッシュボード特化UIフレームワーク
  - Tailwind CSS + Rechartsベースで構築
  - 35以上のコンポーネントを提供（チャート、KPIカード、テーブル等）
- 状態管理（Redux, Zustand, Jotai など）

#### 5-2. バックエンド

- 言語・フレームワーク（Node.js/Express, Python/FastAPI, Go など）
- API設計（REST, GraphQL, tRPC など）
- 認証・認可（Auth0, Clerk, NextAuth など）

#### 5-3. インフラ・データベース

- ホスティング（Vercel, AWS, GCP, Cloudflare など）
- データベース（PostgreSQL, MySQL, MongoDB, Supabase など）
- ストレージ（S3, Cloudinary など）

#### 5-4. その他ツール

- CI/CD（GitHub Actions, GitLab CI など）
- モニタリング（Sentry, LogRocket など）
- 分析ツール（Google Analytics, Mixpanel など）

#### 5-5. 技術選定の理由

- 各技術を選んだ理由
- 開発スピード、コスト、スケーラビリティの観点
- 代替案とトレードオフ

### 6. 実装ロードマップ作成

段階的な開発計画を策定：

#### 6-1. Phase 1: MVP開発（1〜3ヶ月）

- コア機能の実装
- 基本的なUI/UX
- ベータ版リリース

#### 6-2. Phase 2: 機能拡張（3〜6ヶ月）

- ユーザーフィードバックに基づく改善
- 追加機能の実装
- パフォーマンス最適化

#### 6-3. Phase 3: スケール・成長（6ヶ月〜）

- マーケティング強化
- 収益化の本格化
- 組織・チーム拡大

#### 6-4. マイルストーン設定

- 各フェーズの具体的なゴール
- KPI設定（ユーザー数、売上、エンゲージメントなど）
- リスクと対策

### 7. 企画書の作成と保存

全ての分析・設計内容を企画書としてまとめる：

#### 7-1. ファイル保存

1. 適切なファイル名を生成（例: `web-service-plans/task-management-saas.md`）
2. 企画書を`web-service-plans/`ディレクトリに保存
3. ファイルパスをユーザーに通知

#### 7-2. 企画書フォーマット

詳細なフォーマットは **TEMPLATES.md** を参照してください。

### 8. 次のステップの提案

企画完了後、以下のアクションを提案：

- **プロトタイピング**: Figma、Adobe XDなどでデザイン作成
- **技術検証**: 主要機能のPoC（Proof of Concept）実装
- **ランディングページ作成**: 事前登録・興味喚起のためのLP
- **初期ユーザー獲得**: ターゲットユーザーへのヒアリング
- **開発着手**: 実際のコーディング開始
  - フロントエンド実装時は `/frontend-design` スキルを使用すること

## 実行例

### ユーザー入力例

```
新しいタスク管理SaaSを作りたいです。
リモートワークのエンジニアチーム向けで、Slackと連携できるものを考えています。
予算は個人開発レベルで、3ヶ月でMVPをリリースしたいです。
```

### 実行フロー

1. 初期ヒアリング（不足情報を質問）
2. アイデアブレインストーミング（3パターン提案）
3. ユーザーが選択したアイデアで市場分析（WebSearch使用）
4. MVP機能設計（コア機能3〜5個）
5. 技術スタック選定（Next.js + Supabase + Vercelなど提案）
6. 開発ロードマップ作成（3ヶ月計画）
7. 企画書を`web-service-plans/task-management-saas.md`に保存
8. 次のステップを提案（LP作成、ユーザーインタビューなど）
